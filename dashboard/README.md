# MAM Box Model Dashboard

Interactive Dash app (`mam_dashboard.py`) that writes a namelist, runs `gcmambox`
and animates the results (gases vs time, dm/dlogD by species, dN/dlogD by mode).

## Running

```bash
cd GCMAMBOX/dashboard          # any directory works, see "Paths" below
python mam_dashboard.py        # conda env: gcenvpy
# then open http://localhost:8050
```

For debugging the Fortran side, run the binary directly in `run/`
(it has the namelist and symlinks to the optics files in `opt_data/`):

```bash
cd GCMAMBOX/run && ./gcmambox
```

## Inputs exposed in the UI

- Time: `mam_dt`, `mam_nstep`
- Process switches: gaschem, gasaerexch, rename, newnuc, coag
- Met: `mtmin/mtmax` [K], `mrhmin/mrhmax` [0-1 fraction, not %], `press` [Pa]
- Gases: `qso2`, `qh2so4`, `qhno3`, `qnh3`, `qsoag`, `qhcl`
- Accommodation coefficients: `accom_coef_h2so4/hno3/hcl/nh3`
- Aerosol: `masstot` per mode + mass fractions per species and mode

The namelist is generated by `write_namelist()`; keep it in sync with the
namelist groups read in `src/driver.F90` (`&time_input`, `&cntl_input`,
`&met_input`, `&chem_input`; `&emis_input` is optional and not exposed yet).

## How a run works

Each click on "Run Simulation" creates a temp dir (`/tmp/mam_sim_<session>_*`),
copies `gcmambox` + the 10 optics `.nc` files into it, writes `namelist`, runs
the binary (30 s timeout), reads `mam_output.nc`, then deletes the temp dir.

## Dev notes

### Paths
- `gcmambox` and `assets/` are resolved relative to the script
  (`SCRIPT_DIR`), not the launch directory. The executable is read directly
  from `../modbin/gcmambox` (PR #11), where CMake puts it, so rebuilding
  updates the dashboard automatically. The old local symlink
  `dashboard/gcmambox` is no longer used.
- `assets/` must contain all 10 optics files (same as `opt_data/`). If any is
  missing the dashboard refuses to run and lists them.
- History: launching from `run/` used to pick up `run/assets/` (logos only),
  so `gcmambox` ran without optics tables and segfaulted in `mam_aero_lw`
  (`mam_opt.F90`). `gcmambox` now stops with `ERROR STOP ... cannot open
  optics file` instead.

### User documentation
- The "Doc !" button opens `/doc`, a Flask route that renders
  `../doc/doc_gcmambox.md` to HTML with the python `markdown` package. If that
  package is not installed (e.g. on a server), the page renders the .md in
  the browser with marked.js from jsdelivr, and shows plain text only if the
  CDN is unreachable. Edit the .md and reload the page.

### Run length and animation size
- Default and presets use `mam_dt = 300` s (GEOS-Chem chemistry step).
- `MAX_STEPS` (2000): longer runs are refused, to protect a shared server
  (the binary also has a 30 s timeout).
- `MAX_FRAMES` (150): the animation keeps every k-th step (plus the last);
  the gas curves keep every step. Frames are built as plain dicts (no Plotly
  validation): ~1 s per figure, page 10-13 MB for 150 frames; lower
  `MAX_FRAMES` if that is too heavy on a server.
- Tested with the server versions (`uv.lock`: plotly 7.1, dash 4.5) and with
  the local conda env (plotly 5.19, dash 2.14).
- Shorter steps or MOSAIC substeps remove numerical NH3 oscillations
  (nucleation case: 60 s, or 5 substeps).

### Debugging a failed run
- The dashboard shows only the binary's **stderr**; most model prints go to
  stdout and are lost.
- The temp dir is deleted in the `finally` block, so the namelist that failed
  is lost too. To reproduce, rebuild the namelist with the same values and run
  `gcmambox` in `run/` (or temporarily skip the `rmtree`).

### Debug mode
- `app.run(debug=True, host='0.0.0.0', port=8050)`: hot reload + browser dev
  tools. Speed cost is small (a second watcher process, ~170 MB, a few % CPU;
  unminified JS on first page load); callbacks run at normal speed.
- **Security**: debug mode enables the Werkzeug interactive debugger (arbitrary
  Python execution behind a PIN) and `0.0.0.0` exposes it on the network.
  Fine on a trusted machine; for anything shared use `debug=False` or
  `host='127.0.0.1'`.
- Hot reload means edits to `mam_dashboard.py` are picked up without restart.
